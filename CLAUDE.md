# Opportunity Hunter — правила для агента

## Деплой и любые операции на сервере — только через приватный SSH

1. На сервер ходим **только по приватному адресу** (Tailscale или другая частная сеть):
   `$HermesPrivateServer` в приватном файле настроек (`OH_SETTINGS_FILE`, по умолчанию
   `~/Projects/hermes-platform/scripts/local.settings.ps1`). Публичный адрес (`$HermesServer`)
   **не используется никогда**: ни для деплоя, ни для проверок, ни «временно, пока приватный не работает».
2. **Сначала проверка подключения, потом работа:** `python3 scripts/vps.py --check`.
   Все операторские скрипты (`vps.run`, `deploy_plugin.py`, `import_profile.py`, `telegram_setup.py`)
   делают эту проверку сами перед любой командой.
3. **Если вход или заливка не прошли — остановись и сообщи пользователю, где застряло**
   (стадия из `PRIVATE_SSH_FAILED at …`: network / login / host key, либо шаг заливки и его вывод).
   Никаких повторов в цикле, фоновых ретраев и «подождём, пока отпустит».
4. Ключ хоста закреплён: при входе по приватному адресу он сверяется с ключом сервера
   (`$HermesHostKeyAlias`). Не отключай `StrictHostKeyChecking` и не правь `known_hosts` без пользователя.
5. Если приватного подключения нет или оно не настроено (`PRIVATE_SSH_NOT_CONFIGURED`) — скажи
   пользователю, а не обходи защиту.

## Порядок заливки
бэкап (`scripts/backup_gateway.py`) → `scripts/deploy_plugin.py --env OH_BACKUP_DIR=…`
→ перезапуск только профиля opportunity-hunter → проверка (PID Gateway не изменился,
default-профиль не тронут). В Git Bash переменные с путями `/opt/...` передавай с `MSYS_NO_PATHCONV=1`.

## Публичный репозиторий
- В git не попадают: персональные данные (в том числе в тестовых примерах), адреса и имена хостов,
  пути сервера, секреты, `tmp/`, `runtime/`, мастер-профиль. Перед коммитом — поиск утечек по diff;
  нашёл — не коммить, пока не исправишь.
- Пушить только явно указанные ветки (`git push origin <branch>`), никогда `--all` / `--mirror`.
- Без соавторов и подписей ассистента в коммитах и PR.
