## Что изменится после отдельного разрешения

В default config будет задан `gateway.multiplex_profiles: true`; после финальной проверки credentials и свободного окна будет снят `gateway.parked` и выполнен один перезапуск **только** `/run/service/gateway-default` через установленный S6ServiceManager. Проверены его run/finish и `s6-svstat`; новый запуск будет выполнять тот же `hermes gateway run --replace` от hermes. Docker restart/recreate не нужен. Текущие диалоги Gateway прервутся; другие контейнеры не перезапускаются.

Второй профиль учитывается автодетектором multiplex уже при следующем запуске Hermes. Поэтому до согласованного окна не следует выполнять посторонний перезапуск Gateway; marker удерживает новый профиль выключенным. Даже явное удаление multiplex-ключа не заменяет удаление второго профиля из обнаруживаемого дерева при полном откате.

Cron остаётся PAUSED на этапе подключения. Живые Telegram, модель, поиск A/B/C/D, уведомления и пять агентных Cron-выполнений проверяются только в следующем этапе. В этой версии обычный `cronjob(action='run')` отказывает при paused; принудительный trigger может одновременно возобновить задачу. Для ручных проверок потребуется контролируемый порядок, исключающий гонку с расписанием; нельзя считать PAUSED совместимым с любым вариантом run. Регулярные задания разрешается включать только после успешного согласованного теста.

## Откат

Готов `scripts/rollback_gateway.py`, его копия лежит рядом с последним приватным snapshot. Выполнен **только PLAN ONLY**: проверены backup/config hash, допустимые абсолютные пути и отсутствие symlink. Действительное выключение/восстановление сервиса не тестировалось, поскольку это запрещено текущим разрешением.

Полный возврат: припарковать новый профиль; штатно остановить gateway-default; сохранить новый профиль целиком вне `data/profiles/` в `<HOST_ROOT>/disabled-profiles/opportunity-hunter-<UTC>`; атомарно восстановить только исходный config.yaml с его правами; штатно запустить gateway-default через s6; проверить старый Telegram, соседний сервис и ресурсы. Скрипт требует `--apply` и проверенный текущий config hash; без них только вывод плана. Данные нового профиля сохраняются, ничего не удаляется. Старый auth.json, env, Cron и базы при обычном откате **не восстанавливаются из устаревшего снимка**, чтобы не потерять актуальную OAuth-ротацию и текущую работу.
