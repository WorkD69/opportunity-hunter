# Opportunity Hunter MVP

Персональный исследовательский профиль Hermes v0.21.6. Поиск не ограничен реестром сайтов: родной `web_search` чередует русские и английские запросы и автоматически регистрирует новые страницы. Известные источники проверяются независимо по категориям; `web_extract` вызывается только для изменившихся страниц. Выбор и проверку условий выполняет Hermes, SQLite сохраняет подтверждённые факты и историю.

**Статус 18.10.2026:** многопрофильный Gateway активирован с разрешения владельца; default и opportunity-hunter подключены. Telegram, отдельные OAuth-сессии, поиск A–D, SQLite/избранное и повтор уведомлений проверены. Все пять Cron PAUSED, планировщик не запускался. OAuth-сессии относятся к одному аккаунту Codex и делят квоту. Результаты, ошибки покрытия и ограничения: `reports/ACTIVATION-LIVE.md`.

## Локально

Требуется Python 3.12+, дополнительных зависимостей у прикладного кода нет.

```powershell
python -m unittest discover -s tests -v
python -m opportunity_hunter.cli build
python -m opportunity_hunter.cli init
python -m opportunity_hunter.cli profile
python -m opportunity_hunter.cli health
```

`build/opportunity-hunter` — переносимый **припаркованный**, неактивный профиль без секретов. Повторная сборка поверх существующего каталога запрещена; для новой проверки задайте другой пустой `--output`, оканчивающийся на `opportunity-hunter`. Команды CLI не развёртывают систему и не отправляют сообщения. Данные локальной проверки лежат только в `runtime/`, исключённом из Git.

## Операторские скрипты

`scripts/` — разовые и сервисные операции с VPS (подготовка профиля, бэкап, активация, откат, диагностика). Запуск через `python scripts/vps.py <script.py> [--container] [--env KEY=VALUE]`. Все данные хоста лежат только в приватном файле настроек оператора вне репозитория (путь по умолчанию — `~/Projects/hermes-platform/scripts/local.settings.ps1`, переопределяется `OH_SETTINGS_FILE`):

| Настройка | Назначение | Переменная на сервере |
|---|---|---|
| `$HermesServer`, `$HermesIdentityFile` | SSH-доступ (закреплённый ключ хоста) | — |
| `$HermesHostRoot` | корень развёртывания Hermes на хосте | `OH_HOST_ROOT` |
| `$OpportunityBotUsername` | ожидаемое имя Telegram-бота профиля | `OH_BOT_USERNAME` |
| `$HermesProtectedService` | соседний сервис, который нельзя затрагивать | `OH_PROTECTED_SERVICE` |

Каталог конкретного бэкапа передаётся явно: `--env OH_BACKUP_DIR=<путь>`.

## Telegram после подключения

Пишите: «Найди оплачиваемые Python-стажировки», «Какие новые возможности за три дня?», «Почему подходит #ID?», «Сохрани #ID», «Отключи турниры». Общение обрабатывает обычный Hermes, не отдельный классификатор сообщений.

Кнопки-команды под уведомлением позволяют сохранить, скрыть, открыть детали и запросить повторную проверку. Также доступны `/oh_saved`, `/oh_list B`, `/oh_details ID`, `/oh_save ID`, `/oh_hide ID`, `/oh_instructions ID`, `/oh_profile`, `/oh_health`, `/oh_category A off`, `/oh_frequency B 12`. Команда `/oh_recheck ID` ставит отметку и подсказывает запрос; кнопка «Повторно проверь предложение» запускает обычный диалог с агентом и проверку точной страницы.

Профиль меняется через обсуждение: агент показывает предложение правки и выдаёт `/oh_confirm TOKEN`. Только сообщение владельца в личном Telegram-чате подтверждает изменение. Токен одноразовый, срок 30 минут, привязан к версии профиля. Нет инструментов для подтверждения от лица модели.

Категории: A — личные стипендии, денежные призы и целевые гранты; B — работа и стажировки; C — бесплатные торговые соревнования; D — бесплатное обучение и карьерные программы. Неподтверждённые сведения остаются неизвестными. Числовой ранг служит сортировке полезности и не является вероятностью успеха.

## Регулярность и бюджеты

Пять **родных** Cron-задач: четыре независимых проверки в 08:05/08:20/08:35/08:50, 14:xx и 20:xx по Москве и общая сводка в 21:00. Перед поиском проверяется наступление срока: A24 ч, B12 ч, C24 ч, D48 ч по умолчанию. Настройка частоты применяется на ближайшем таком тике; ночью поиска по умолчанию нет. Ошибка откладывает повтор минимум на четыре часа. Задания сначала создаются приостановленными.

Одна проверка: до двух разнообразных запросов, до четырёх страниц. Текст читается порциями по 12000 символов; кэш ограничен 60000 символами. Нельзя отметить страницу обработанной, пока не прочитаны все порции; слишком длинная страница остаётся неполной. Общий дневной предел обёртки в SQLite:12 поисковых запросов и 16 извлечений; все категории и ручные запросы делят бюджет. Прямые встроенные web-инструменты остаются доступны Hermes: лимит не является общей квотой модели или всех её инструментов. Навык предписывает использовать обёртку. Повторный одинаковый запрос в течение часа использует кэш. GET с ETag/Last-Modified, текстовые хеши с сохранением ссылок, robots.txt, ограничение размера 2 МБ, проверка публичных адресов/перенаправлений и задержки хоста.403/CAPTCHA/авторизация не обходятся. Платный резерв не включается.

Общий поиск сериализован арендой в SQLite. Это не ограничивает всю память или CPU другого профиля в общем процессе Gateway. Неизменённая страница не возвращается модели после успешной обработки. Если обработка прервалась, кэш остаётся для повторного разбора; `complete_pages` отдельно отмечает завершение по категории. Устаревшие условия не обновляются догадкой. Поисковые ошибки видны в `/oh_health`, а не превращаются в сообщение «ничего нет».

## Что сохраняется

Отдельный `opportunities.db`: предложения, доказательства, критерии, версии/изменения, даты, источники и связи с категориями, профиль/его предложения правок, предпочтения, избранное/скрытие, уведомления и результаты запусков. Внутренний `state.db` Hermes не модифицируется нашим кодом. `identity_url` обозначает конкретную программу/вакансию; общий URL правил не используется как её уникальный идентификатор.

Отправка уведомления атомарно захватывает запись. Успех фиксирует Telegram message_id; неопределённый сетевой исход или прерванная отправка автоматически не повторяются. Состояния `unknown`/`sending` требуют сверки оператором, чтобы не создавать дубли. Абсолютная доставка «ровно один раз» через сеть не гарантируется.

## Границы MVP

Без заявок, аккаунтов, откликов работодателям, почты, браузера и торговых подключений. Будущие анкеты/версии подтверждений можно привязать к ID предложения и версии профиля, но модуль подачи сейчас отсутствует. Содержимое сайтов рассматривается как недоверенные данные. Новому профилю не подключаются MCP рабочих проектов, терминал, файловые инструменты, делегирование, личный Chrome и чужая память.

Профиль в общем Gateway обеспечивает логическое разделение, не файловую или процессную песочницу. Общими остаются пользователь ОС, исполняемый код, лимиты контейнера, отказы Gateway и квота модельного аккаунта. Доступ к файлам соседнего проекта не предоставляется через инструменты нового профиля; принудительной защиты от злонамеренного Python-плагина на уровне ОС в этой схеме нет.

См. `docs/AUDIT.md`, `docs/ACTIVATION.md`, `reports/live-search.md` и `reports/TESTING.md`.

## Результат проверки

68 автоматизированных тестов; журнал `reports/unit-tests.log`. Реальный бесплатный backend установленного Hermes вернул результаты по всем четырём направлениям. Потоковый запуск HTTP-кода на VPS прочитал 2 из 3 официальных страниц: третья превысила лимит 2 МБ и сохранена как ошибка. `reports/replay_evidence.py` повторяет обработку этих сохранённых ответов локально: реестр новых источников, две карточки с точными цитатами, избранное, пропуск неизменённых страниц, два имитированных уведомления и ноль повторных. Это воспроизведение ответов, не живой агентный запуск.

Для новых находок за 3 дня инструмент использует `recent_days=3`; `days=3` отдельно означает близкие дедлайны. Качественная оценка пользы, сложности регистрации, нагрузки, совмещения и долгосрочной ценности явно отделена от подтверждённых критериев. Неизвестные значения остаются `unknown`, числовые шансы отбора не принимаются.
