# Раздельная настройка credentials

Настройку выполняет оператор; владельцу нужны только ввод секрета в скрытое поле, `/start` новому боту и подтверждение входа на официальной странице OpenAI. Gateway остаётся parked, multiplex не включается, пять Cron остаются PAUSED.

## Диагностика предыдущего сбоя

Проверены Windows PowerShell 5, разбор исходного PS1, загрузка SSH settings, наличие identity и реальная передача синтетического ввода через прежний SSH pipeline. Синтаксических ошибок PS1 нет; сервер получил ввод и вернул ожидаемый exit 1. Путь профиля правильный, uid=10000, профиль 0700, .env 0600; реальное создание/удаление пробного файла прошло. Ошибка кавычек в первоначальном диагностическом `python -c` касалась только самой новой пробы; она исправлена и не является установленной причиной старой настройки.

Старые подробные журналы попыток отсутствуют. Поэтому невозможно доказать, на каком действии завершилась конкретная попытка владельца. Воспроизведён дефект старого обработчика: при валидном токене и недоступном `/start` он отклоняет настройку до записи `.env`. Локальный PS1 закрывал форму до SSH и не сохранял этапы/exit codes; исключение могло завершить окно, а следующий OAuth пропускался. Это подтверждённые дефекты процедуры, но не доказанная историческая цепочка событий. Старый обработчик сохранён в новом профиле как configure_telegram.previous.py; тест воспроизведения использует только искусственные credentials, временный каталог и имитацию API.

## Telegram

`Start-OpportunitySetup.ps1` запускает только `telegram_setup.py`. Скрытое поле реализовано Tk, GUI остаётся открытым при ошибках. Python передаёт токен через subprocess stdin непосредственно в `ssh -T` → `docker exec -i` → операторский обработчик; токена нет в argv, командной истории и журналах. Raw SSH stdout/stderr не выводятся и не сохраняются. Клиент принимает только фиксированные публичные коды и сверяет их с exit code.

Обработчик проверяет принадлежность ожидаемому боту (имя задаётся в приватных настройках оператора), отсутствие совпадающего токена или bot ID в других профильных .env и отсутствие webhook. Валидный токен сохраняется атомарно, права 0600, немедленная проверка чтением. Отсутствие `/start` возвращает exit 20 / SEND_START, сохраняя токен. `--finish` повторяет получение ID без передачи секрета; `--check` проверяет готовую настройку. ID берётся только из приватного `/start`, совпадение sender/chat и allowlist старого Hermes обязательны. Старые файлы читаются только для проверки, не меняются. Все три поля ID и token проверяются повторным чтением.

Если GUI недоступен, оператор открывает `telegram_setup.py --terminal` в обычном интерактивном терминале. Он использует getpass; без TTY отказывается работать. Это отдельный резервный путь, автоматически одновременно с GUI он не запускается.

Локальный журнал `reports/setup-events.jsonl` содержит только UTC, этап, фиксированный код и exit code. Серверный `operator/setup-events.jsonl` имеет 0600 и содержит только UTC/этап/код. Не включать PowerShell transcript или вывод содержимого .env. Нельзя логировать raw urllib/httpx исключения: они могут содержать URL с Telegram-токеном.

## OAuth

Запускается отдельно `oauth_session.py` только после успешного Telegram. `profile_oauth.py` повторно проверяет Telegram, очищает process environment, задаёт HOME/HERMES_HOME/cwd нового профиля и umask 077. Python audit hook запрещает чтение/запись чужих auth.json/auth.lock/.env/.credentials.json; глобальный OAuth fallback обязан быть пустым. Запускается штатный Hermes v0.21.6:

`hermes -p opportunity-hunter auth add openai-codex --label opportunity-hunter --no-browser`

Native device login работает внутри hermes-agent. В поток вывода пропускаются только официальный URL auth.openai.com/codex/device, одноразовый пользовательский код и фиксированный статус ожидания. Код не пишется в файлы журналов. Native exit code и наличие собственного access/refresh материала после сохранения проверяются без раскрытия значений. Независимый запрос модели выполняется отдельным activation_auth_probe.py с запретом чужих credential files и проверкой, что выбранный token принадлежит собственному pool. Основной auth/config/env не заменяются резервными копиями.

Живые Telegram-уведомления, поиск и Cron не входят в этот этап. Переход к Gateway требует отдельного разрешения; регулярное расписание — другого подтверждения после живых тестов.
