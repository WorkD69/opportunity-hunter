## Сравнение

| Вариант | Дополнительные ресурсы, оценка | Разделение и риски | Обслуживание/решение |
|---|---|---|---|
| A: навыки+Cron в default | немного Python/SQLite, без второго Gateway | память/сессии/инструменты/канал общего проекта; нужны изменения его состояния | самый короткий запуск, не подходит требованию независимости |
| B: отдельный профиль и общий Gateway | ориентир 20–120 МБ пиковых дополнительных данных/контекста, без весов модели и фонового демона; точный замер только после запуска | отдельные память/сессии/конфигурация/Cron/MCP/секреты при корректном scope; общий UID, процесс, квоты и область отказа | выбран;1 раз разрешить активацию/перезапуск; обновление не нужно |
| C: отдельный контейнер | второй Python/Gateway ориентир 300–500 МБ RAM; тот же digest делит слои образа, не копирует 4.55 ГБ полностью | разделение процессов/томов/лимитов сильнее; общий VPS остаётся | оправдан при необходимости жёстких лимитов/изоляции или измеренной нестабильности B; сейчас необходимость не доказана |

Оценки RAM не являются результатом запуска нового профиля. SQLite и код малы; исходные страницы ограничены размером, дневные бюджеты фиксированы. Любое увеличение VPS или платная интеграция требует отдельного решения. Поиск использует VPS и удалённую модель, Windows/Ollama/Chrome/Tailscale не являются его зависимостями.

CPU: у A/B нет нового постоянно работающего интерпретатора; при поиске возникают короткие всплески сетевой обработки и SQLite на том же 1vCPU. Модель удалённая. C добавляет второй Gateway/Python и его фоновое обслуживание; при одновременных заданиях все варианты конкурируют за один VPS. Пиковый CPU полного нового агента ещё не измерен. Диск: переносимый профиль B114018 байт, ZIP36720 байт, пример SQLite274432 байта; A имел бы сопоставимый прикладной объём, C дополнительно требует writable-layer и журналов второго контейнера, но при том же digest делит существующие слои образа. Кэш/история растут по мере обнаружения URL; дневные лимиты не являются лимитом общего размера базы. Новой оплаты инфраструктуры для A/B не требуется при имеющемся запасе; для C необходимость увеличения VPS не доказана.

После проверок: контейнеры продолжают работать, hermes-agent в пределах лимита, запас RAM и диска сохранился, соседний systemd-сервис active. `reports/server-health-after.json` содержит снимок. Разница с первым снимком не является замером нового профиля: он не запускался, фоновые сервисы живут своей нагрузкой.

## Проверенные исходные интерфейсы установленной версии

- `hermes_cli/gateway_multiplex_mode.py`: single-profile guard, необходимость второго профиля и нового старта, сохранение `gateway.multiplex_profiles:true` в default config; состояние `served_profiles=[]`, причина `only one profile exists (nothing to multiplex)`.
- `hermes_cli/gateway_multiplex_served.py`: live served_profiles является источником истины; rescan помогает уже многопрофильному Gateway и не превращает нынешний одиночный процесс в него.
- `hermes_cli/plugins.py`, `plugins_discovery.py`, `plugins_loader.py`, `plugins_manifest.py`: `plugin.yaml`+`__init__.py/register(ctx)`, опт-ин `plugins.enabled`, scoped register_tool, register_command, dispatch_tool.
- `gateway/run_inbound.py:1079+`, `gateway/session_context.py`: команды плагина получают ContextVar с user/chat/profile до входа в модель; это используется для подтверждения изменения профиля.
- `agent/secret_scope.py`: get_secret применяет контекст профиля и при отсутствии scope в мультиплексоре не берёт чужой os.environ. Плагин не читает токен через os.getenv.
- `tools/web_tools.py`: родные web_search/web_extract; `plugins/web/keyless_mcp.py`: Exa free явно существует безAPI-ключа. Поисковик не реализуется заново.
- `tools/cronjob_tools.py`, `cron/jobs.py`: родные create/list/run, skills/enabled_toolsets/deliver/paused, per-profile Cron store. `hermes_time.py`: профильный timezone поддерживается.
- `tools/mcp_tool.py`: scoped соединения. MCP рабочих проектов не переносятся; новый сервер MCP не нужен.
- Profiles/Memory/Sessions/Skills: состояние привязано к Hermes home; новый профиль создаётся без clone. Собственная структурированная таблица фактов нужна для проверяемой фильтрации; native memory не дублирует её биографией.
- Chromium найден `/opt/hermes/tools/chromium-1208/chrome-linux64/chrome`; в текущей конфигурации browser off, активный сценарий использует Windows CDP. Для MVP браузер не нужен. Delegation/дочерние агенты не включаются из-за отсутствия необходимости и бюджета.
