## Доступы владельца

1. Создать нового бота в BotFather и один раз открыть его личный чат. Токен в переписку с агентом не вставлять.
2. В частном `.env` **нового профиля**, права 0600, задать TELEGRAM_BOT_TOKEN и одинаковый числовой ID владельца в TELEGRAM_ALLOWED_USERS, TELEGRAM_HOME_CHANNEL, OH_OWNER_ID. Старый токен/allowlist не копировать. Сверить отсутствие дублирования токена с default только булевым результатом, без вывода значений.
3. Выполнить отдельный OAuth-вход `hermes -p opportunity-hunter auth add openai-codex` штатным способом. Перед активацией убедиться, что login записался в собственный auth.json; корневой auth.json не копировать и не менять. Учётная запись модели может быть существующей, её квота будет общей. Автоматический платный fallback не настраивать.

После разрешения каталог создаётся только новым; существующий профиль с таким именем не перезаписывается. Сборка имеет gateway.parked: его снимают лишь после проверки credentials, preflight и согласованной активации. Воспользоваться штатным механизмом Gateway текущей установки; не использовать docker restart. Точную команду перезапуска сверить с активным supervisor перед выполнением.

## Cron

В новой профильной среде `install_cron.py` использует родной `cronjob` и создаёт задачи PAUSED, не перезаписывая существующие имена. Не записывать jobs.json вручную. Перед установкой проверить изолированный HERMES_HOME и окружение без корневых секретов. Живые тесты выполняются напрямую без запуска Cron. `cronjob run` в установленной версии может требовать возобновления задачи; без отдельного разрешения владельца его не использовать. Расписание по Москве находится в cron-spec.json. Пять установленных задач пока не включать.

## Проверки и откат

Проверить served_profiles (default+opportunity-hunter), разные bot adapters, собственные MCP/toolsets/profile memory, конфигурации и хеши старых Cron. Выполнить тестовые команды владельца/чужого пользователя, Telegram-кнопки, поиск всех категорий, профильную правку/подтверждение, новое уведомление/дубль/сводку. Измерить пик RAM/CPU/время, сравнить здоровье старых сервисов. Проверку обычного поиска при выключенном Windows провести фактически; наличие VPS-архитектуры не заменяет её.

Быстрое отключение нового профиля: штатно припарковать его, остановив его Cron/адаптеры без остановки default. При сбое Gateway поставить gateway.parked в каталоге нового профиля операторским доступом и восстановить Gateway штатным supervisor. Полный возврат к исходному одиночному режиму: сохранить новый профиль вне `profiles/` под проверенным абсолютным путём, восстановить исходную настройку multiplex из резервной копии, затем повторно запустить Gateway. Одного удаления ключа из config при оставшихся 2 профилях недостаточно — код снова включит multiplex. Перемещения/восстановление выполняются только в рамках согласованного отката, с проверкой путей; удалять данные/образы не нужно.
